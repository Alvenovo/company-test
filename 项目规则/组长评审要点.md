# 组长评审要点与易忽略点清单

> 写前门禁在设计规范 §1.2 / §4。本文件管读评审 xlsx，以及仍值得对照的评审句。组长新意见先泛化进设计规范 §4，本需求特有的字段值不在这里堆。

## A. 数据与业务校验

1. **数据库字段校验（“下同”规则）**：列表/页面展示的业务字段，步骤和预期必须同步核对数据库对应字段；同一批同类用例全部补。
2. **列表 + 详情双范围**：同时有列表和【查看详情】时，两边字段都核。
3. **状态流转后的“另一侧”**：上下架、移入/移出后检查目标列表字段；再次操作后必须是最新一次。
4. **批量操作**：覆盖全部对象 + 字段顺序与配套展示。

## B. 筛选 / 搜索

5. **新增筛选字段专项**：检查展示、位置与可搜索性；成功标准行齐了再写。
6. **正反向输入**：正向 + 反向（错误值、空格、表情、特殊符号、不存在值）各成一步，预期一一对应。
7. **匹配规则**：先确认精确/模糊、SPU/SKU/货号等语义，不混用标识。

## C. 日志 / 经营口径

8. **反向断言**：不应产生的记录不存在；库存/销量/发布数量/同步按规定不增加时，步骤里核对「未增加 / 未同步」。
9. **日志位置先确认**：页面还是库表、失败是否记录，确认后再写预期。
10. **待确认逻辑**：材料没有的值标「待确认」，不编造。

## D. 场景合理性

11. **权限 / 隔离**：先确认账号与店铺/角色关系；设计上有、本机缺账号则建条标受阻。
12. **弱校验 / 强校验**：同一流程里保存与提交校验强度不同时拆开测，见设计规范 §4.11。

## 读取组长评审 xlsx 的固定方法（每次一致，不再试错）

1. 用 .NET ZipFile（`[System.IO.Compression.ZipFile]::ExtractToDirectory`，或复制为 .zip 后用 Expand-Archive）把评审 xlsx 解压到临时目录。
2. 读取 `xl/comments1.xml`：组长批注正文，每条 comment 带 `ref="单元格"`（如 H2、E7）和 author（如 TEST）。
3. 读取 `xl/drawings/vmlDrawing1.vml`：批注标记位置（`<x:ClientData>` 里的 Row/Column，0 基），与 comments 对应。
4. 读取 `xl/sharedStrings.xml` 和 `xl/worksheets/sheet1.xml` 映射真实值：sheet1 中 `t="s"` 的 `<v>` 是 sharedStrings 索引，不是真实值。
5. 批注行号对应用例：第 2 行 = TC_XXX_001，第 3 行 = 002，依此类推；E 列=用例名称列，H 列=预期列。表中若出现成功标准原文行（无用例编号），按设计规范 §1.2 落成可执行用例，不当成已有用例名。
6. 不依赖 artifact-tool 的 thread/note 检查，不渲染成图片做识别。
7. 按批注改回查看版 xlsx（直接覆盖，不另存 `-改正后`），并同步 CSV / 执行状态清单 / 执行过程；源 JSON 为唯一数据源。导出后把 `.xlsx.inspect.ndjson` 移出正式文件夹。
