## 0. 环境与账号准备（必读）

### 平台后台（配置装修用）
- 地址：https://dev-mall-admin.njsyue.com
- 账号：`wwd`，密码：本机凭据，不入库
- PC 装修：左侧「商城装修 / PC装修」→「首页装修」→ 打开已发布页面（如 `wwd测试`）→【装修】进入编辑器，组件含「商品楼层」「广告楼层」。
- 手机装修：左侧「手机装修」→「首页装修」（URL https://dev-mall-admin.njsyue.com/decorate_m/lists），页面支持 Android / IOS / WAP / 微信小程序 平台切换；测试页如 `wwd-test`。

### 商户后台（上下架商品用）

- 账号：`wwd`，密码：本机凭据，不入库
- 商品列表：https://dev-mall-seller.njsyue.com/goods/goods_list（可对商品执行上架/下架）；仓库中商品：https://dev-mall-seller.njsyue.com/goods/goods_storage_list

### 前端入口
- PC 商城：https://dev-mall-pc.njsyue.com/store/
- H5（WAP）：https://dev-mall-m.njsyue.com/
- 微信小程序 / Android App / iOS App：以测试环境提供入口为准（提供入口后补充到本手册）。

### 需求说明（2026.08.12 迭代）
- 背景：装修中配置的商品未上架时，原逻辑显示白底占位图，运营无法及时关注。
- 本次逻辑：覆盖 PC 端、移动端所有涉及商品组件显示的地方，未上架商品不显示，后续商品自动补齐。
- 示例1：配置8个商品、2个未上架 → 第一行正常显示4个上架商品，第二行显示2个上架商品。
- 示例2（极端）：配置8个商品、7个未上架 → 第一行最左侧显示仅有的1个上架商品，第一行空缺3个区域，第二行全部空缺。
- 通用判断标准：组件内不出现白底占位图/白框；上架商品按配置顺序前移；空位只留在末尾；商品上下架后刷新页面结果实时一致。

### 测试数据准备
- 在 PC 装修/手机装修中准备测试页面或复用 `wwd测试` / `wwd-test` 页面，商品组件配置 8 个测试商品（命名如 `wwd装修测试_01~08`）。
- 通过商户后台对指定商品执行上架/下架，构造：全部上架、部分未上架（开头/中间/末尾/间隔）、全部未上架、仅1个上架等场景。
- 配置或发布装修页面后，再打开对应前端核对，避免缓存干扰。

## 一、PC 商品组件用例（商品楼层，2 条）

### TC_PC商品组件_001（P1）未上架商品不显示与补齐全流程（中间/首尾下架、极端、恢复）

- **前置条件**：平台后台已配置PC首页装修「商品楼层」组件（配置8个商品且全部上架）；页面已发布；商户后台可执行上下架。
- **备注**：PC 装修中放置商品的组件为「商品楼层」。执行时在商品楼层组件上验证。
- **步骤**
  1. 打开PC商城首页「商品楼层」组件，核对8个上架商品完整显示（2行4列）；强制刷新（Ctrl+F5）后再次核对。
  2. 商户后台将中间2个商品（第3、4位）下架，打开/刷新PC商城首页「商品楼层」组件核对。
  3. 商户后台将首位（第1位）和末位（第8位）商品下架，打开/刷新PC商城首页「商品楼层」组件核对。
  4. 商户后台将剩余上架商品继续下架至仅剩1个（如第7位），再全部下架，打开/刷新PC商城首页「商品楼层」组件核对。
  5. 重新上架其中部分商品，打开/刷新PC商城首页「商品楼层」组件核对。
- **预期**
  1. 8个上架商品完整显示（2行4列），无白底占位图、无白框；刷新后结果一致。
  2. 中间未上架商品不显示，剩余6个按配置顺序前移：第一行4个、第二行2个，无白框（对应需求8配2示例）。
  3. 首位/末位未上架商品不显示，剩余商品继续前移补齐，无白框（首尾位置覆盖）。
  4. 仅剩1个上架时展示在首行最左侧、其余空缺且无白框（对应需求7未上架极端示例）；全部未上架时组件空白无白框、页面无报错。
  5. 商品恢复显示，按配置顺序展示，布局正常。
- **通过标准**：5 项预期全部满足。

### TC_PC商品组件_002（P2）装修配置变更发布、专题页同规则、后台配置可见性与广告组件不受影响

- **前置条件**：平台后台可编辑PC首页装修「商品楼层」组件；已配置PC专题装修页（商品组件含未上架商品）；首页含广告/图片组件；均已发布。
- **备注**：PC 装修中放置商品的组件为「商品楼层」。执行时在商品楼层组件上验证。
- **步骤**
  1. 编辑「商品楼层」组件，将配置商品减少至3个并保存发布，打开PC商城首页核对。
  2. 增加配置商品至8个并发布，刷新后核对。
  3. 打开PC商城对应专题页，核对商品组件展示。
  4. 打开PC商城首页，核对广告/图片等非商品组件展示。
  5. 在平台后台装修编辑器中打开「商品楼层」组件配置，核对未上架商品在配置列表中是否仍展示。
- **预期**
  1. 3个商品单行展示，其余空位无白框。
  2. 按新配置展示数量与顺序正确，无白框/占位图异常。
  3. 专题页未上架商品不显示、后续商品补齐，无白框。
  4. 广告/图片组件正常显示，不受商品补齐逻辑影响，页面布局无错乱。
  5. 未上架商品在后台配置中仍可见（带未上架标识），便于运营处理，不影响前端显示逻辑。
- **通过标准**：5 项预期全部满足。

- **步骤**
  1. 打开商城首页，抓取商品组件相关接口响应，核对未上架商品数据的返回与过滤。

- **预期**

  2. 在不同分辨率/机型下打开移动端首页商品组件，核对展示。

  1. 各浏览器均按新逻辑展示，无JS报错，无白框残留。
  2. 移动端补齐逻辑正常，无遮挡错位、无白框。
  3. 页面正常加载无卡死，未上架商品不显示、补齐逻辑正常。
- **通过标准**：3 项预期全部满足。
