## 2. Agent 用得顺手的 6 个关键机制

### 2.1 项目级 AGENTS.md（规则即代码）

把"团队约定"写进项目根目录的 `AGENTS.md`，Agent 每次开工自动读取并遵守：

- 测试环境入口清单（地址、账号、登录方式、验证码流程）
- 用例编写规范（覆盖维度、合并精简原则、步骤/预期编号格式）
- 归档规则（四件套、证据、命名）
- 红线（禅道只读、测试环境写操作先确认、数据保留）

好处：换新对话、换人操作，规则不丢；不用每次重复交代。

### 2.2 会话交接.md（跨对话不丢进度）

每个项目根目录维护一份 `会话交接.md`，记录"任务进度 / 环境状态 / 下一步待办"，新对话第一步先读它。

好处：上下文不够开新对话时，Agent 能自己接着干，不需要用户重新讲一遍已知信息。

### 2.3 技能（Skills）

Codex 支持按需加载技能：

- 用例生成类：按团队 12 列格式生成禅道导入 CSV、XLSX
- 组长评审读取类：固定方法解压 xlsx 读批注生成改正版
- 文档类：周报、提效总结等固定格式输出

用法：直接说"用 xxx 技能生成"，或让 Agent 判断任务匹配的技能自动调用。

### 2.4 受控浏览器 + 自动化脚本（登录态与操作复用）

- 调试端口 `9222`：测试环境/禅道；`9223`：飞书专用
- `browser_auto.mjs`：打开页面、截图、无痕窗口（`newctx`/`usectx`/`ctxlist`/`disposectx`）
- 验证码固定流程：页面内 fetch 原图 → base64 保存 → PIL 8 倍放大 → 发用户确认，**不再试错**

好处：登录态持久复用；图形验证码等人工环节按固定流程一次走通；多账号用无痕窗口隔离可并行在线。

### 2.5 测试数据台账

新建的测试数据统一命名 `codex测试_日期` 并登记台账（名称、页面、字段、查看路径、清理方案）。

好处：数据可追溯、他人可检查、后续清理有依据。

### 2.6 证据归档规范

每条用例对应一个 `证据\用例X_证据\` 文件夹，只放关键证据，文件名含用例编号；共享证据复制到每个相关用例；配套《实测证据清单》做"用例 ↔ 证据 ↔ 证明内容"映射。

好处：结论有据可查，复盘、排错、回归对比都方便。

## 3. 常用操作流程（快速上手）

### 3.1 生成一套测试用例（禅道需求 → 四件套）

1. 提供需求号/禅道链接 + 需求文档 + 模块范围。
2. Agent 按项目 AGENTS.md 的用例规范生成源数据 JSON。
3. 检查要点：最少用例覆盖最多场景、高频易忽略点（数据库字段核对、正反向输入、状态流转、日志反向断言等）。
4. 由 JSON 一键生成：禅道导入 CSV（12 列）、查看版 XLSX（自动换行/自动行高）、执行状态清单、执行过程手册。
5. 校验：CSV 12 列且条数与 XLSX 一致、步骤与预期一一对应。
6. 归档到 `D:\测试用例\{项目}\{执行日期}\{需求名-负责人}\`。

### 3.2 处理组长评审意见（xlsx 批注）

1. 收到 `-reviewed by` 的 xlsx。
2. Agent 用固定方法：解压 xlsx → 读 `xl/comments1.xml` 批注 → 映射 `sharedStrings.xml` + `sheet1.xml` 定位单元格 → 按行号对应用例编号。
3. 按批注修改源 JSON → 重新生成全套 → 输出 `-改正后.xlsx`，移走临时副产物。

### 3.3 执行用例并留证

- 自动化能做的（接口操作、上下架、截图、抓包）交给脚本；人工环节（手机 App 核对、扫码）由人配合。
- 每条用例至少留一个**能区分通过与失败**的关键证据。
- 受阻用例如实标注"当前环境受阻"，并写清手动测试要点，**禁止把未验证写成已验证**。

### 3.4 定位 bug 的方法论（本周验证有效）

1. 复现类问题：先确认现象 → 排除数据缺失 → 找关键变量（如接口返回顺序/时序）→ 做对照实验验证因果。
2. 图片/资源类问题：区分"没渲染"与"加载失败"→ 直接请求资源看 HTTP 状态 → 读错误返回体定位 key/路径问题。
3. 回归验证：批量跑 N 轮统计通过率，用数字判断"是否真的修好"，不凭感觉。

### 3.5 环境登录（多端自动登录）

- 按项目入口清单顺序依次登录；登录态有效直接复用，不重复登录。
- 需要验证码时按固定流程抓取、放大、发用户确认；短信码触发后索取，不乱序、不一次性索要全部。
- 多账号场景使用无痕窗口隔离，互不串号。

## 4. 让 Agent 更"方便"的 10 个技巧

1. 一次说清三要素：**目标 / 约束 / 交付物格式**（例："按团队 12 列格式生成禅道导入 CSV"）。
2. 给足上下文入口：禅道链接、需求号、页面路径、账号信息，减少 Agent 摸索。
3. 让 Agent 先读项目 `AGENTS.md` 和 `会话交接.md` 再动手。
4. 交付物格式直接引用已有规范，改一必全同步（源 JSON 为唯一数据源）。
5. 测试环境写操作先让 Agent 报"要做什么、影响什么、是否清理"，确认后再执行。
6. 结论要求量化：复现轮次、接口顺序、HTTP 状态、通过率，不用"好像偶现"。
7. 证据求精不求多：一个证据能证明结论就不堆砌。
8. 环境无法执行时要求标注"当前环境受阻"并给出手动测试要点，而不是跳过或硬编结果。
9. 涉及多文件改动时明确要求同步校验（CSV 列数、条数、编号、步骤-预期对应）。
10. 会话收尾时让 Agent 更新 `会话交接.md`，保持"最后更新"日期，超 150 行及时精简/拆分。

## 6. 红线与注意事项

- **禅道严格只读**：只能查看，禁止创建/编辑/删除/导入/改状态/评论，除非用户明确要求写回并确认。
- **测试环境写操作先确认**：创建/编辑/删除/上下架等先说明操作对象与影响范围，经同意后执行。
- **测试数据保留不清除**：命名 `codex测试_日期` 并登记台账；清理需先提出方案再执行。
- **验证码固定流程**：抓原图 → 8 倍放大 → 发用户确认；错误/过期重新获取，不换其他方式试错。
- **未验证不写已验证**：执行状态如实标注，受阻项给手动测试要点。
- **登录态复用**：有效时不重复登录；Chrome 重启后无痕窗口需重新登录。

## 8. 常见问题（FAQ）

**Q1：它能做什么、不能做什么？**
能做：用例生成、脚本化复现 bug、抓接口/截图、批量数据核验、文档生成、环境登录。不能做：需要人工扫码/短信码、无源码的小程序自动化、无权限的数据库校验；这些需人配合。

**Q2：验证码怎么办？**
按固定流程：Agent 抓取验证码原图 → 放大 → 发给你确认 → 你回填；不会反复试错，登录态会持久复用。

**Q3：会不会改坏测试环境数据？**
不会擅自改。规则要求写操作先报方案经确认后执行；测试数据保留并登记台账，可追溯、可清理。

**Q4：新开对话 Agent 不认识我了怎么办？**
新对话会先读项目 `AGENTS.md` 和 `会话交接.md`，进度和规则自动恢复；关键是会话结束时记得让 Agent 更新交接文档。

**Q5：Agent 出错/结论不对怎么办？**
要求它给证据（接口返回、截图、日志关键行）；拿证据对照排错；同时把这些坑补进项目规则，下次自动规避。
