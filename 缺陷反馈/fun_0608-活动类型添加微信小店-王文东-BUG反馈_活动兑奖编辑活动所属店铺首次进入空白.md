# BUG 反馈：活动兑奖-编辑活动时「所属店铺」首次进入显示空白

## 基本信息

| 项 | 内容 |
|---|---|
| Bug 标题 | 编辑活动时「所属店铺」字段首次进入显示空白，二次进入恢复 |
| 所属产品/模块 | 华硕小二 / 管理后台 / 兑换活动管理-活动兑奖 |
| 缺陷类型 | 前端显示缺陷（接口数据正确） |
| 优先级 / 严重程度 | P1 / 严重（影响编辑回显与二次审核确认） |
| 发现人 / 日期 | 王文东 / 2026-08-12 |
| 环境 | https://dev-asus.njsyue.com（测试环境），账号 19552261935 |

## 复现步骤

1. 登录华硕小二后台，进入【兑换活动管理】→【活动兑奖】列表。
2. 选择任意活动点击【编辑】（如审核通过活动 wmw抽奖实物20250925002，编码 0N31，ID 147）。
3. 观察「所属店铺」字段是否显示（预期显示 华硕商城/华硕商城）。
4. 返回列表再次点击【编辑】，观察该字段。
5. 打开抓包/开发者工具，观察 `cms/prize/detail` 与 `cms/common/storeList` 两个接口的返回先后。

## 实际结果

- 当 `detail` 接口先于 `storeList` 返回时，「所属店铺」输入框为**空白**（label 为空）；当 `storeList` 先返回时显示正常。
- 实测 20+ 轮，**接口返回顺序与空白 100% 对应**：detail 先返回 → 空白；storeList 先返回 → 正常。
- 活动 147 自然复现 6 轮中 2 轮空白；活动 118（未通过）自然复现 6 轮中 2 轮空白；强制延迟 `storeList` 3 秒后，通过/待审核/未通过三种状态**必现空白**。
- `detail` 接口返回数据始终正确（如 147：storeId=33、platformId=7、platformStoreName=华硕商城-华硕商城），日志/接口无异常。

## 预期结果

- 首次进入编辑页「所属店铺」即应正常回显，不依赖两个接口的返回顺序。
- 多次进入显示结果一致，接口数据正确时页面不应空白。

## 根因分析（推断）

编辑页进入时并行请求活动详情（`cms/prize/detail`，含 storeId/platformId）与店铺级联数据（`cms/common/storeList`）。前端在 detail 返回后即设置级联控件值，但此时 storeList 选项尚未加载完成，antd Cascader 无法把 value 解析为对应 label，界面显示空白；storeList 先返回时选项已就绪，value 可正常解析显示。首次进入更容易触发（storeList 首次网络请求较慢），二次进入时 storeList 可能走缓存更快返回，因此表现为「第一次空白、后续正常」。

## 影响范围

- 与活动审核状态无关：**审核通过、待审核（未审核）、未通过**三种状态活动均存在（强制时序必现）。
- 涉及所有含「所属店铺」字段的兑换活动编辑场景（活动转盘、福袋、直播间抽奖、微信小店等类型共用该编辑页）。

## 证据

### 接口证据

- `cms/prize/detail`（活动 147）：`"storeId":33,"platformId":7,"omsCode":"asus888","platformStoreName":"华硕商城-华硕商城"` —— 数据正确。
- `cms/common/storeList`：华硕商城平台下含 storeId=33（华硕商城）、37（重庆华硕商城）。
- 复现轮次接口顺序（活动 147）：
  - R1: detail→storeList，所属店铺 label=`""`（空白）
  - R2: detail→storeList，所属店铺 label=`""`（空白）
  - R3~R6: storeList→detail，所属店铺 label=`华硕商城 / 华硕商城`（正常）

## 修复建议

- 编辑页在 detail 返回后，先等待/合并 storeList 数据完成再设置级联控件值；或 storeList 完成后重新回填一次已设置的值。
- 更稳妥：detail 与 storeList 用 Promise.all 合并后统一回填表单；或 detail 中直接返回平台店铺名用于 label 回显兜底。
